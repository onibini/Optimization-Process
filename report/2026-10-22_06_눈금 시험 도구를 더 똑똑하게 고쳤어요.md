# 눈금 시험 도구를 더 똑똑하게 고쳤어요 (아직 계산용 컴퓨터에는 안 보냈어요)

- 날짜: 2026-10-22
- 지난번 시험에서 **"합격하는 눈금이 없다"**는 결과가 나왔죠. 그래서 시험 도구를 고쳤어요.
- **계산용 컴퓨터에는 보내지 않았어요.** 이 컴퓨터에서 입력 파일 만들기와 테스트만 했어요. 확인해 주시면 보낼 거예요.

---

## 1. 합격 기준을 어떻게 바꿨나요?

처음 기준은 이랬어요.

> "정확해야 하고, **그리고** 지금 눈금보다 시간이 10% 넘게 늘면 안 돼요."

그런데 정확한 눈금은 점이 많이 필요해서 둘 다 만족하기가 어려웠어요. 그래서 이렇게 바꿨어요.

> "**정확한 것이 먼저**예요(전체 0.1%, 부표 하나하나 0.3% 이내). 시간은 **'같은 정확도를 얻는 보통 눈금(균일 눈금)'과 비교**해요."

달리기 시합에 비유하면 이래요. 예전에는 "작년 기록보다 10%만 느려도 합격"이었다면, 이제는 "**같은 점수를 받으려면 보통은 20분 걸리는데, 새 방법은 몇 분 걸리나?**"를 비교하는 거예요. 보통 방법보다 빠르면 합격이에요.

## 2. 시험 도구에 더한 것

1. **더 좁은 촘촘 구간 후보:** 공진 위치 예측값의 0.8~1.0배, 0.85~1.0배 구간만 촘촘하게 하는 눈금. 구간이 좁을수록 점이 적어서 빨라요. (지난 시험에서 실제 공진은 예측값의 0.91~0.96배에 있었어요.)
2. **더 촘촘한 "정답용" 기준:** 지난번 기준(0.0125 간격)보다 두 배 촘촘한 0.00625 간격을 새 기준으로 써요. 기준이 정말 믿을 만한지도 확인할 수 있어요.
3. **보통 눈금 후보도 더 넣었어요:** 간격 0.05(지금), 0.025, 0.0125. "같은 정확도를 얻는 보통 눈금"을 찾으려고요.
4. **주파수별 계산 값 저장(덤프):** 눈금마다, 파도 빠르기마다의 값(부표 흔들림, 전기 뽑는 장치의 힘 등)을 파일로 저장해요. 지난번에 **"구간을 넓혔더니 오히려 더 틀린"** 이상한 결과의 이유를 찾는 데 써요.
5. **"전기 뽑는 장치"가 정해지는 자리 알아내기:** 컴퓨터는 가장 크게 흔들리는 자리를 기준으로 전기 뽑는 장치(PTO)의 세기를 정해요. 그 자리가 어디인지를 표에 적어요. 눈금이 성기면 이 자리를 잘못 고를 수 있어서 중요해요.
6. **결과 표(summary.csv) 정리:** 시험 프로그램을 돌린 줄에 쓸데없는 칸(최적화 알고리즘 등)이 채워지던 것을 비웠어요.

## 3. 어떻게 확인했나요?

이 컴퓨터에서 **계산 없이** 확인했어요.

- 입력 파일과 눈금 점의 개수 확인. 예를 들어 크고 깊은 부표에서는 이렇게 나와요.

| 눈금 | 점의 개수 |
| --- | --- |
| 지금 (보통 0.05) | 51 |
| 0.85~1.0 구간만 촘촘 | **51** (지금과 같은 개수!) |
| 0.8~1.0 구간만 촘촘 | 54 |
| 0.7~1.0 구간만 촘촘 | 61 |
| 기준 (0.00625 간격) | 401 |

- 합격·불합격을 가리는 규칙이 맞게 움직이는지 **자동 테스트**로 확인했어요(경계값 0.1/0.3 포함).
- 예전에 남아 있던 진짜 계산 결과 파일로, "전기 뽑는 장치가 정해지는 자리"를 정확히 찾아내는지 시험했어요(딱 맞았어요).

## 4. 앞으로 어떻게 되나요?

1. 확인해 주시면 **빠른 시험**을 계산용 컴퓨터에 보내요. 예상 시간은 **약 15분**이에요(지난번 8분 반보다 길어요. 기준이 더 촘촘하고 후보가 늘어서요).
2. 결과로 **어느 구간이 합격**하는지 보고, 이상했던 결과의 이유도 찾아요.
3. 합격한 눈금이 정해지면 그때 **진짜 프로그램에 넣어요.** (아직 안 넣었어요.)

## 낱말 풀이

| 낱말 | 쉬운 뜻 |
| --- | --- |
| 균일 눈금 | 간격이 모두 같은 보통 눈금 |
| 기준 | 비교할 때 "이게 정답에 가장 가깝다"고 삼는 아주 촘촘한 결과 |
| 덤프 | 계산 중간의 값들을 통째로 파일에 옮겨 적어 두는 것 |
| PTO | 부표가 흔들리는 힘으로 전기를 뽑아내는 장치 |
