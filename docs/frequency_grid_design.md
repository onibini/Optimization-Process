# 설계안: WAMIT 주파수 점 수 정렬(NCPU)과 공진 인식 주파수 격자

- 작성: 2026-10-22 (구현 전 설계안, 승인 후 구현)
- 전제: 최적화 알고리즘(DE)은 바꾸지 않고, 형상+배치 동시 최적화를 유지합니다. WAMIT 검증은 계산용 PC(Ryzen 7 9700X, 8코어/16스레드)에서 합니다.

## 1. 왜 필요한가

WAMIT 평가 시간은 주파수 점 수에 거의 비례하고, 현재 주파수 격자는 0.5~3.0 rad/s를 0.05 간격 51점으로 고정입니다.

1. **정확도 문제:** 균일 0.05 격자는 좁은 공진(R=2.5, D=5.0에서 ω≈1.13, RAO 7~11)을 놓쳐서 파워를 약 +4% 과대평가했습니다(보고서 10: 51점 17,940 W, 201점 17,229 W). `rao_calc.py`는 격자에서 RAO가 최대인 점의 방사 감쇠를 `B_pto`로 쓰므로 격자가 성기면 `B_pto`도 부정확합니다.
2. **시간 문제:** 점이 51개인데 WAMIT은 NCPU개씩 라운드로 계산합니다(매뉴얼 14.6절: 주파수 수가 NCPU의 배수일 때 효율이 최대). NCPU=8이면 51=6×8+3이라 7라운드를 돌고 마지막 라운드는 3개만 계산합니다.
3. 공진에서 먼 곳은 RAO가 매끄러워서 성긴 격자로 충분하고, 공진 부근만 촘촘해야 합니다.

## 2. 현재 동작 (코드 위치)

| 항목 | 위치 | 동작 |
| --- | --- | --- |
| 격자 생성 | `wamit_handler.omega_grid(omega_max)` | 0.5 + 0.05k, `OmegaMax`까지 (기본 3.0, 51점) |
| `.pot` 출력 | `write_pot_file` | `-N NPER` + `0.5 0.05 PER` (시작·간격 형식) |
| RAO와 `B_pto` | `rao_calc.calculate_rao_matrix` | 파일에서 읽은 주파수 전부 사용, RAO 최대점의 방사 감쇠를 `B_pto`로 |
| 적분 | `power_calc.calculate_power` | `scipy.integrate.simpson(y, x=omegas)` (불균일 간격 가능) |
| 병렬 | `config.wam`의 `NCPU` | WAMIT이 주파수를 NCPU개씩 라운드로 계산 |

## 3. 설계 A: 주파수 점 수를 NCPU의 배수로 (`FreqAlign`)

- **설정 (`[WAMIT Settings]`):** `FreqAlign` = `0` 끔(기본) / `1` 올림 / `2` 내림.
  - `1` 올림: 점 수를 NCPU의 배수까지 늘립니다. 마지막 라운드가 어차피 비어 있으므로 **시간은 그대로**이고 점이 늘어 정확도가 좋아집니다(51점이면 56점). 추가 점은 가장 넓은 간격을 둘로 나누며, 간격이 같으면 공진 추정 주파수 가까운 쪽부터 나눕니다.
  - `2` 내림: 가장 높은 주파수부터 빼서 배수로 줄입니다(51점이면 48점, `OmegaMax`가 2.85가 됨). 시간이 줄지만 작은 WEC의 고주파 공진을 자를 수 있어 큰 WEC 전용입니다.
- 기대 효과(이 PC 실측): 51점에서 48점으로 5.8초가 5.4초(약 7%). 8코어 이후 NCPU를 더 올려도 효과는 작았습니다(NCPU 8이 5.4초, 17이 4.6초).
- **계산용 PC:** 9700X는 물리 코어 8개이므로 `NCPU=8`이 기본이고(매뉴얼은 하이퍼스레드가 아니라 물리 코어 수를 권장), 점 수는 48/56/64입니다. 16으로 올리는 효과와 메모리 한계 변화는 검증 항목입니다.
- 균일 격자와 적응형 격자 모두에 적용됩니다.

## 4. 설계 B: 공진 인식 격자 (`FreqGrid = adaptive`)

- **설정:** `FreqGrid` = `uniform`(기본, 현재와 같음) / `adaptive`.
- **공진 추정:** 부가질량을 뺀 수압학적 상하동요 고유진동수 `ω0 = sqrt(g / (D + 2R/3))` (원통+반구의 `C33/m`). 실제 피크는 부가질량과 배열 간섭으로 더 낮아지므로 R=2.5, D=5.0에서 피크 1.125~1.15 rad/s는 `ω0 = 1.213`의 0.93~0.95배입니다.

  | R | D | ω0 (rad/s) |
  | --- | --- | --- |
  | 2.5 | 5.0 | 1.21 |
  | 1.5 | 2.5 | 1.67 |
  | 0.5 | 2.0 | 2.05 |
  | 2.5 | 0.5 | 2.13 |
  | 0.5 | 0.5 | 3.43 (기본 상한 3.0 밖) |

- **격자 규칙:**
  1. 기본은 0.05 간격 격자(현재와 동일).
  2. `[0.7·ω0, 1.0·ω0]` 구간만 미세 간격(0.0125 또는 0.025)으로 대체. 미세 점은 0.0125 격자 위에 놓아 성긴 점과 겹치게 합니다.
  3. 선택: `ω > 1.5·ω0`에서는 0.1 간격으로 성기게(꼬리).
  4. 점 수가 NCPU의 배수가 되도록 `FreqAlign`을 적용.
- **점 수 예산 (prototype, 상한은 max(3.0, 1.2·ω0)로 키움):**

  | R, D | 균일 | 미세 0.0125 | 미세 0.025 | 미세 0.025+꼬리 | 위 격자 +올림(8) | +내림(8) |
  | --- | --- | --- | --- | --- | --- | --- |
  | 2.5, 5.0 | 51 | 73 | 59 | 47 | 48 | 40 |
  | 1.5, 5.0 | 51 | 74 | 59 | 48 | 48 | 48 |
  | 0.5, 2.0 | 51 | 88 | 64 | 64 | 64 | 64 |
  | 2.5, 0.5 | 51 | 90 | 64 | 64 | 64 | 64 |
  | 0.5, 0.5 | 74 | 136 | 95 | 95 | 96 | 88 |

  큰 WEC은 `미세 0.025+꼬리`로 균일 51점 수준의 시간에 맞출 수 있고, 작은 WEC은 공진이 높아 점이 많아집니다(상한이 3.0을 넘어서).
- **이미 확인된 것 (실측, R=2.5, D=5.0, 배치 A):** 공진 부근 0.0125 간격을 포함한 49점 비균일 격자가 201점 균일 격자와 0.02% 차이(51점 균일은 +4.1%)였고 시간은 같았습니다. 0.025 간격은 0.3% 차이였습니다.
- **알려진 위험과 대응:**
  - 추정 구간이 실제 피크를 놓치면 성긴 균일 격자 수준으로 돌아갑니다(더 나빠지지는 않음). 안전장치로 피크가 미세 구간의 가장자리나 밖이면 경고합니다(후속으로 구간을 옮겨 재계산하는 옵션을 검토).
  - `ω0`가 `OmegaMax`를 넘는 작은 WEC(R=0.5, D=0.5 등)은 공진이 격자 밖입니다. 현재도 절단 경고가 뜹니다. 옵션: 상한을 자동으로 `max(OmegaMax, 1.2·ω0)`까지 키움(고주파에서 파장 대비 패널 크기는 작은 WEC일수록 충분히 작음).
  - **결과가 달라집니다.** `B_pto`와 적분이 정확해지므로 기존 균일 격자 결과(약 +4%)와 직접 비교가 안 됩니다. 논문과의 연속성을 위해 기본은 끄고(`uniform`), 새 계산에만 선택합니다.
- **적합성 확인:** `simpson`은 불균일 간격을 지원하고(scipy 1.17), `.pot`에 주파수를 직접 나열하는 방식은 실측으로 동작을 확인했습니다. 주파수 파일(.1/.3)의 값이 입력과 같은 표기라 `rao_calc`의 키 매칭이 유지됩니다.

## 5. 구현 범위 (승인 후)

- `wamit_handler.py`: `build_omega_grid(radius, draft, omega_max, mode, align, ncpu)`; `write_pot_file`이 균일·정렬 끔이면 지금과 **완전히 같은 `.pot`**을, 아니면 주파수 목록(`NPER` + 나열)을 씁니다.
- `config.cfg`/`main.py`: `FreqGrid`, `FreqAlign` 검증과 출력, 문제 설정에 전달.
- 선택: 피크가 미세 구간 가장자리일 때 경고(`power_calc` 또는 `rao_calc`).
- 테스트: 기본값에서 `.pot` 동일, 점 수와 배수, 미세 구간 포함, 격자 정렬 성질, 잘못된 설정. 검증용 스크립트의 함수가 같은 규칙이므로 테스트를 재사용합니다.
- 문서: README, `docs/architecture.md`, 기술 보고서, `report/`, CHANGELOG.

## 6. 검증 계획 (계산용 PC)

검증용 스크립트 `scripts/experiments/freq_grid_study.py`는 이미 준비했습니다(`src/`는 바꾸지 않고, 같은 규칙의 후보 격자를 만들어 `.pot`의 주파수 목록만 바꿔 WAMIT을 돌립니다). 이 PC에서는 실행하지 않고 `--dry-run`(입력 생성만)과 단위 테스트로만 확인했습니다.

| 연구 | 내용 | 사례 | 예상 시간(i5 기준 추정, 9700X는 다를 수 있음) |
| --- | --- | --- | --- |
| `grids --quick` | 후보 격자 대 0.00625 기준격자(401~585점), 파워 오차·개별 WEC 오차·공진 위치, 판정, 주파수별 덤프 | 4개 형상 × 배치 A | 약 20분 (첫 시험 8.5분에서 기준격자와 후보가 늘어남) |
| `grids` | 위와 같음, 전체 | 9개 형상 × 배치 2개 | 약 40분 |
| `ncpu` | NCPU와 점 수(48/51/56/64) 대 시간 | R=2.5, D=5.0 | 약 10분 |
| `limit` | NCPU별로 WAMIT이 받는 최대 패널 수(메모리 한계) | 3개 형상 | 약 15분 |

**판정 기준 (2026-10-22 개정, 기준 (a)):** 정확도를 우선하고, 시간은 같은 정확도의 균일 격자와 비교합니다.
1. 정확도: 0.00625 간격 균일 기준격자 대비 총 파워 오차 0.1% 이내, 개별 WEC 최대 오차 0.3% 이내.
2. 시간: 후보의 시간 ≤ (정확도 기준을 만족하는 균일 격자 중 가장 빠른 것의 시간). 균일 후보는 0.05, 0.025, 0.0125이고, 모두 불합격이면 기준격자 자체의 시간이 기준입니다. 판정 상수 `TIME_RATIO_MAX = 1.0`(스크립트 상단)에서 조정합니다.
3. 점 수가 NCPU의 배수(정렬 후보에서 확인).
4. 모든 사례에서 `peak_over_w0`(RAO 최대점 / ω0)와 `peak_unctrl_over_w0`(`B_pto`를 결정하는 비제어 피크 / ω0)가 구간 안(밖이면 구간을 넓힘).
5. `limit`: 계산용 PC의 한계가 이 PC(전체 약 1,100패널)와 얼마나 다른지 확인하고 `PANEL_MEMORY_WARN`을 조정.

판정 결과는 `logs/freq_grid_study_grids_verdict.csv`와 실행 마지막의 요약 표(후보별 정확/시간/통과 사례 수)로 나옵니다. 사례마다 `logs/dump_<R>_<D>_<배치>_<격자>.csv`에 주파수별 `S`, 5기의 `B_k`(방사 감쇠), `rao_k`, `bpto_k`, `density_k`(`b·ω²·rao²·S`)가 저장되어 격자 간 차이를 주파수별로 비교할 수 있습니다(`--no-dump`로 끔).

**후보 격자 (개정):** 기준 `ref_uniform_0.00625`; 균일 `0.05`(현재), `0.025`, `0.0125`; 적응형 `0.7~1.0`, `0.8~1.0`, `0.85~1.0`(모두 미세 0.0125와 꼬리 0.1), `0.8~1.0`+미세 0.00625; 가장 좁은 구간 `0.85~1.0`의 NCPU 올림/내림 정렬. 첫 시험(`2026-10-22_06` 보고서)에서 0.025 간격은 부족했고 꼬리 0.1은 정확도에 영향이 없었으며, 실제 공진은 `0.907~0.957·ω0`에 있었습니다.

**2차 개정 (2026-10-22, 시험 도구):** 적응형 `0.85~1.1`(미세 0.0125, 0.00625)를 추가했고, R=0.5·D=2.0에는 0.003125 확인 격자(801점)를 더했습니다. 또 모든 격자를 같은 WAMIT 실행에서 두 방식으로 평가합니다: `node`(현재: 비제어 RAO 최대 격자점의 `B`)와 `interp`(최대점과 양옆 두 점의 포물선 꼭짓점에서 `B`를 2차 보간). 보간은 시험 도구 안에서만 재현하며 `src/physics/rao_calc.py`는 바꾸지 않았습니다(적용 여부는 결과를 본 뒤 별도 승인).

**3차 개정 (2026-10-23, 시험 도구):** 3차 시험에서 `B_pto` 보간(`interp`)이 개별 WEC 오차를 줄이지 못해 시험 도구에서 뺐습니다. 대신 **2단계 격자**를 후보로 넣었습니다(`two_stage_fwhm6`, `two_stage_fwhm10`): 1단계는 균일 0.05 실행이고, 그 결과에서 WEC마다 비제어 RAO 피크와 공진 폭(`fwhm ~ 2·B_kk / (M + A_kk)`)을 추정해, 피크 ±max(4·폭, 0.1) 창 안을 폭/n(n=6, 10)에 맞는 간격(0.003125, 0.00625, 0.0125)으로 2단계에서 추가 계산합니다. 시간과 점 수는 1단계+2단계 합산이며, 판정 기준 (a)는 그대로입니다. 좁은 공진은 간격이 반치폭의 약 1/6~1/10이어야 한다는 3차 시험 결과에 따른 것입니다.

**실행에 필요한 준비 (구현 완료, 아래 `-Script` 옵션):** `scripts/remote.ps1 submit`에 `-Script`/`-ScriptArgs`(스크립트와 인자를 스냅샷 안의 `_job.json`으로 전달)와 `-DryRun`(계산용 PC에 연결하지 않고 스냅샷 확인)이 추가되었습니다. 사용법은 `docs/remote_compute.md` 2-1절에 있고, 결과 CSV는 `logs/` 아래에 쓰므로 기존 `fetch`가 가져옵니다.

```powershell

.\scripts\remote.ps1 submit -Name fgrid_quick -Script scripts/experiments/freq_grid_study.py -ScriptArgs "--study grids --quick" -Wait
.\scripts\remote.ps1 submit -Name fgrid_ncpu  -Script scripts/experiments/freq_grid_study.py -ScriptArgs "--study ncpu" -Wait
```

## 6-1. 구현 상태 (2026-10-23)

`FreqGrid`(0 균일, 1 적응형 0.85~1.1 + 미세 0.00625 + 꼬리 1.5·ω0 이상 0.1 간격)를 구현했습니다(기본 0). 2단계 격자와 `FreqAlign`, `OmegaMax` 자동 확장은 구현하지 않았습니다. 보고서: `docs/reports/2026-10-23_04_freq-grid-option.md`.

## 7. 결정 사항 (2026-10-22 승인) 및 상태

1. 새 격자(`FreqGrid=adaptive`)는 **기본 끔**. 검증 통과 후 새 계산에만 선택합니다.
2. `ω0 > OmegaMax`인 작은 WEC에서 상한을 자동으로 키우는 것은 **선택 옵션**(기본 끔)으로 둡니다.
3. 판정 기준은 처음에 **총 파워 0.1% / 개별 WEC 0.3% / 시간 +10%**였고, 첫 시험 후 **기준 (a)**(정확도 0.1%/0.3% 우선, 시간은 같은 정확도의 균일 격자와 비교)로 바꿨습니다(6절).
4. `remote.ps1`에 `-Script` 옵션 추가를 승인했고 **구현·로컬 시험을 마쳤습니다**(`docs/reports/2026-10-22_05_remote-script-option.md`).

**남은 순서:** (a) 사용자가 확인한 뒤 계산용 PC에 검증 제출, (b) 결과로 구간 비율(0.7, 1.0)과 판정 기준 확인, (c) 통과하면 5절의 구현. 계산용 PC 제출은 사용자의 확인 후에만 합니다.
