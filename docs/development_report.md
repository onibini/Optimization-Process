# WEC 최적화 프로세스 구조 개선 및 병렬화 개발 보고서

## 1. 개요

- 작성일: 2026-10-06
- 대상 프로젝트: WEC Array Optimization
- 주요 대상: 단일 WEC 형상 최적화 및 다중 후보 WAMIT 평가
- 개발 환경: Python 3.12, Windows, WAMIT v7

본 보고서는 기존 WEC 형상·배치 최적화 코드를 GitHub에서 관리 가능한 Python 프로젝트로 재구성하고, 코드 품질과 실행 안정성을 개선한 과정을 정리한다. 특히 WAMIT이 사용할 수 있는 CPU 수가 제한된 상황에서 단일 WAMIT에 모든 자원을 할당하는 대신 여러 후보를 독립 프로세스로 동시에 평가하는 구조를 구현하고 검증하였다.

## 2. 기존 구조의 주요 문제

개선 전 프로젝트에는 다음 문제가 있었다.

1. `src` 자체가 Python 패키지 이름으로 사용되어 설치형 프로젝트 구조가 명확하지 않았다.
2. 빌드 메타데이터가 없어 표준 설치와 배포 패키지 생성이 어려웠다.
3. 최적화 알고리즘이 후보를 순차 평가하여 WAMIT 병렬 실행이 불가능했다.
4. 모든 평가가 하나의 `workspace`를 사용하여 동시 실행 시 파일 충돌 가능성이 있었다.
5. CPU 및 RAM 설정이 WAMIT 프로세스 단위인지 전체 예산인지 명확하지 않았다.
6. 장시간 실행 중 프로그램이 종료되면 알고리즘 상태를 복구할 수 없었다.
7. 실험용 메시 형상과 시각화 코드가 실제 실행 코드에 함께 포함되어 유지보수 범위와 의존성이 불필요하게 컸다.
8. 설정 파서, 알고리즘 입력값, WAMIT 결과 처리에 대한 방어적 검증이 부족했다.

## 3. 프로젝트 구조 개편

프로젝트를 표준 `src` 레이아웃의 설치형 패키지로 변경하였다.

```text
.
├── .github/workflows/       # GitHub Actions
├── docs/                    # 설계 및 개발 문서
├── src/wec_optimization/
│   ├── algorithms/          # DE, PSO, GA, CMA-ES 및 체크포인트
│   ├── data/                # 환경 데이터
│   ├── physics/             # 메시, WAMIT, RAO, 발전량 계산
│   ├── problems/            # 형상, 배치, 통합 최적화 문제
│   ├── utils/               # 좌표 변환 및 기하학 유틸리티
│   └── cli.py               # 명령행 진입점
├── tests/
├── config.cfg
└── pyproject.toml
```

`pyproject.toml`에 패키지 정보, Python 버전, 실행 의존성, 개발 의존성, CLI, pytest 및 Ruff 설정을 통합하였다. 설치 후 다음 명령으로 실행할 수 있다.

```powershell
wec-optimize --config config.cfg
```

또는 다음과 같이 모듈로 실행할 수 있다.

```powershell
python -m wec_optimization --config config.cfg
```

## 4. 코드 품질 및 오류 예방 개선

Ruff의 오류, import 정렬, 잠재 버그, 단순화 및 성능 관련 규칙을 적용하였다. 전체 소스와 테스트는 Ruff 포맷을 사용한다.

주요 수정 사항은 다음과 같다.

- 음수 설정값을 주석 구분자로 잘못 처리하던 설정 파서 수정
- 변수 범위, 차원 수, 반복 횟수 및 개체군 크기 검증
- DE, GA, PSO 및 CMA-ES 계수 범위 검증
- `NaN` 또는 무한대 목적함수 결과 차단
- 지원하지 않는 WEC 수 차단
- 빈 RAO 결과와 잘못된 주파수 배열 검증
- WAMIT 출력의 불완전한 행 처리
- GA 세대 로그가 전체 최적값을 기록하도록 수정
- CLI 종료 시 최적 설계와 목적함수 출력
- 공개 패키지 API 명시
- 중복 또는 사용하지 않는 코드와 의존성 제거

실제 최적화에서 사용하는 원통–반구 형상만 남겨 메시 모듈을 단순화하였다. 원뿔, B-spline 실험 구현과 프로파일 시각화 코드를 제거하면서 `matplotlib` 의존성도 제거하였다. 반구 극점 직전에 미세한 중복 링이 생길 수 있던 문제를 수정하고 관련 메시 테스트를 추가하였다.

## 5. WAMIT 병렬 평가 설계

### 5.1 설계 원칙

WAMIT 평가가 전체 계산 시간의 대부분을 차지하므로, 한 세대의 후보를 먼저 생성한 후 후보 평가를 병렬 실행하도록 변경하였다.

```text
후보 집합 생성
    ↓
격자 양자화 및 대칭 정규화
    ↓
중복 후보와 메모리 캐시 확인
    ↓
신규 후보만 독립 프로세스로 WAMIT 실행
    ↓
결과 수집 및 선택
    ↓
다음 세대 생성
```

Gmsh는 한 프로세스 안에서의 동시 호출에 적합하지 않으며 WAMIT도 파일 기반으로 작동한다. 따라서 스레드가 아닌 별도 프로세스를 사용하고, 각 후보에 다음과 같은 독립 작업 폴더를 할당하였다.

```text
workspace/
├── eval_1_4/
├── eval_2_0/
└── eval_2_3/
```

후보 키는 양자화된 격자 인덱스를 기반으로 생성한다. 동일한 후보가 한 배치 안에 여러 번 나타나거나 이전에 평가된 경우 WAMIT을 다시 실행하지 않는다.

### 5.2 알고리즘별 변경

- DE: 같은 부모 세대를 기준으로 모든 trial vector를 먼저 생성하는 세대형 DE로 변경
- PSO: 모든 입자의 위치를 갱신한 후 한 번에 평가
- GA: 엘리트와 전체 자식 세대를 구성한 후 한 번에 평가
- CMA-ES: 한 세대의 offspring 전체를 생성한 후 한 번에 평가

DE는 기존 순차 갱신 방식과 탐색 경로가 달라질 수 있으나, 현재 방식은 세대 단위 병렬 평가에 적합하고 일반적인 generational DE 구조와 일치한다.

## 6. CPU 및 RAM 예산 관리

`config.cfg`의 WAMIT 설정은 전체 자원 예산을 기준으로 한다.

```ini
[WAMIT Settings]
6     AvailableCPUs
16    AvailableRAMGB
3     ConcurrentRuns
0     KeepWorkspaces
```

실행당 자원은 다음과 같이 계산한다.

```text
실행당 CPU = AvailableCPUs // ConcurrentRuns
실행당 RAM = AvailableRAMGB // ConcurrentRuns
```

현재 예시에서는 WAMIT 프로세스 3개에 각각 CPU 2개와 RAM 5GB를 할당한다. 정수 나눗셈의 나머지는 시스템 과할당을 피하기 위해 사용하지 않는다. 동시 실행 수가 전체 CPU 수를 초과하거나 실행당 RAM이 1GB 미만이면 시작 전에 설정 오류를 발생시킨다.

`RAMGBMAX`는 각 WAMIT 작업 폴더의 `config.wam`에 계산된 실행당 값으로 기록된다.

## 7. 작업 폴더 관리

장시간 최적화에서는 후보별 원시 WAMIT 결과가 디스크를 빠르게 소모할 수 있다. 기본 정책은 다음과 같다.

- 성공한 후보: RAO와 발전량을 계산하고 로그·캐시에 반영한 후 작업 폴더 삭제
- 실패한 후보: 진단을 위해 작업 폴더 보존
- `KeepWorkspaces=1`: 성공한 후보의 원시 파일도 보존

삭제 전 대상 경로가 지정된 작업 루트 바로 아래에 있으며 이름이 `eval_`로 시작하는지 확인한다. 이 검증을 통과하지 못하면 삭제하지 않는다.

실제 WAMIT 평가에서 결과 계산 후 성공 작업 폴더가 삭제되는 것을 확인하였다. 기존 스모크 테스트에서 생성된 성공 작업 폴더 6개도 정리했으며, CSV 최적화 이력은 보존하였다.

## 8. 체크포인트 및 중단 후 재개

범용 영구 캐시 대신 동일한 최적화 실행을 복구하기 위한 세대 단위 체크포인트를 구현하였다.

```ini
[Checkpoint]
1     EnableCheckpoint
1     Resume
1     SaveEvery
0     KeepOnCompletion
```

### 8.1 저장 상태

공통 저장 항목:

- 완료된 세대 번호
- 현재 최적 후보와 목적함수
- 실행 중 평가 캐시
- 평가 및 캐시 적중 횟수
- NumPy 난수 상태
- 설정 fingerprint

알고리즘별 저장 항목:

- DE·GA: population, fitness, WEC별 발전량
- PSO: 위치, 속도, 개인 최적값, 전체 최적값
- CMA-ES: 평균, sigma, 공분산 행렬, 진화 경로, 고유벡터 및 고유값 상태

### 8.2 안전한 저장과 호환성 확인

체크포인트는 먼저 임시 파일에 기록하고 디스크 동기화를 마친 후 원본 파일로 원자적 교체한다. 저장 중 프로그램이 종료되어도 마지막으로 완료된 체크포인트를 유지할 수 있다.

설정 fingerprint에는 알고리즘, 변수 범위, 격자, 개체군 크기, 최대 세대, 환경 조건, 파랑 조건 및 계산 관련 설정이 포함된다. 호환되지 않는 설정으로 재개하려 하면 명확한 오류를 발생시킨다. 병렬 실행 수, 로그 위치, 작업 폴더 보존 여부처럼 수치 결과에 영향을 주지 않는 운영 설정은 재개 중 변경할 수 있다.

정상 완료 시 체크포인트는 기본적으로 삭제된다. `KeepOnCompletion=1`이면 완료 상태로 보존한다. 세대 중간에 종료된 경우 완료되지 않은 세대만 다시 평가한다.

## 11. 현재 제한 사항

1. WAMIT 실행 실패 시 자동 재시도와 timeout 정책은 아직 구현하지 않았다.
2. 실패한 후보 하나가 현재 배치 평가를 중단시킬 수 있다.
3. 체크포인트는 세대 경계에서만 저장되므로 중단된 세대는 다시 평가한다.
4. 실제 동시 WAMIT 실행 수는 WAMIT 라이선스 조건의 영향을 받을 수 있다.
5. 현재 RAO 및 발전량 검증은 기존 계산 모델을 기준으로 하며 별도의 실험 데이터 검증은 포함하지 않는다.
6. 체크포인트는 로컬 pickle 파일이므로 외부에서 받은 신뢰할 수 없는 파일을 사용하면 안 된다.

## 13. 결론

본 개선을 통해 프로젝트는 설치·테스트·배포 가능한 Python 패키지 구조를 갖추었으며, 한 세대의 후보를 미리 생성하고 독립 WAMIT 프로세스로 병렬 평가할 수 있게 되었다. 전체 CPU와 RAM 예산을 동시 실행 수에 맞춰 자동 분배하고, 성공 작업 폴더를 안전하게 정리하여 장시간 실행의 자원 사용을 제어한다.

또한 네 최적화 알고리즘의 전체 상태를 세대 단위로 저장하고 동일 설정에서 복원할 수 있어, 중단 가능성이 높은 장시간 WAMIT 최적화를 실용적으로 재개할 수 있다. 실제 단일 WEC 형상 최적화 시험에서 병렬 실행, 결과 처리, 캐시 및 작업 폴더 분리가 정상 작동함을 확인하였다.
