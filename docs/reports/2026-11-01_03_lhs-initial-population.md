## 1. 개요

[보고서 2026-10-27_01](2026-10-27_01_de100-sites-result.md)에서 DE 100 × 300은 칠발도와 영일만항에서 논문 설계와 다른 골짜기에 수렴했다. 다섯 기가 모두 벽 옆인 설계를 각각 0개, 4개만 평가했다.

탐색 범위는 방파제 앞 실제 설치 해역을 나타내므로 그대로 둔다(사용자 확인). 그래서 범위 안의 탐색을 개선하는 방법으로 초기 개체군을 검토했다.
- 다른 분야의 문헌을 조사했다(균등 난수, LHS, Sobol, 반대점, 카오스, 지식 기반 시딩).
- 사용자는 문제에 대한 가정이 없는 **라틴 하이퍼큐브(LHS)**를 골랐다.
- 시딩("벽 옆 한 줄" 같은 배치를 직접 넣기)은 개방 해역이나 비스듬한 파도에서 맞지 않아 쓰지 않는다.

## 2. 변경 내용

**`lhs_grid_population(pop_size, config)`**
- 변수마다 격자 인덱스 범위(0 ~ `max_idx`)를 `pop_size`개의 같은 폭 구간으로 나눈다.
- 구간마다 한 점을 무작위로 뽑고, 구간 순서를 변수마다 따로 섞는다(McKay, Beckman & Conover 1979).
- 계산 방식: `u = (permutation + rand) / N`, 인덱스는 `floor(u × 격자 점 수)`.
  - 결과가 처음부터 격자 위에 있어서 따로 격자에 맞출 필요가 없다.
  - 격자 점이 개체 수보다 적은 변수(예: R 0.5~2.5는 21점)는 같은 점이 여러 번 나온다.
- 전역 `np.random`을 쓰므로 시드가 같으면 같은 개체군이 나온다.

**`initial_population(pop_size, config)`**
- `config["init_pop"]`(0 또는 1)에 따라 고른다.
- DE, PSO, GA, DEPSO가 `random_grid_population` 대신 이 함수를 부른다.
- 기본값 0은 예전과 같은 난수 호출이어서 결과가 같다.
- CMA-ES는 개체군이 아니라 평균 하나에서 시작하므로 쓰지 않는다. `main.py`가 안내문을 출력한다.

**설정**: `[AlgorithmSettings] InitPop` (0: 균등 난수, 기본, 논문; 1: 라틴 하이퍼큐브).
- `main.py`가 값을 검증하고 `Initial population: Latin hypercube`처럼 출력한다.
- 값은 문제 설정(`*_config.json`)과 `summary.csv`의 `init_pop` 칸에 남는다.

**테스트** (`tests/test_init_population.py`, 10건)
- 값 검증과 기본 설정 파일.
- 범위 안이고 격자 위인지.
- 변수마다 k번째로 작은 점이 k번째 구간에 있는지(층화).
- 양 끝 1/10 구간에 개체 수의 1/10 가까이 들어가는지.
- 격자 점보다 개체가 많을 때.
- 시드 재현성.
- 기본값이 예전 난수 개체군과 같은지.
- DE, PSO, GA가 설정을 따르는지.

## 3. 호환성 영향

- 기본값(`InitPop` 0)의 동작과 결과는 같다. 기존 테스트가 모두 통과했다.
- `summary.csv`에 `init_pop` 칸이 늘었다.
- 사용자가 할 일은 없다.

## 4. 검증

- `ruff check .`, `ruff format --check .` 통과.
- `python -m unittest discover -s tests`: 292건 통과(3건 건너뜀). 보고서 2026-11-01_02의 변경을 포함한다.

**LHS가 실제로 주는 것: 각 변수의 끝 영역을 빠짐없이 덮는다** (그림 (a), (b))
- 5기 동시최적화 범위에서 개체 100개를 2000번 뽑아 셌다.

| 개체 100개 중 | 균등 난수 | LHS |
| --- | --- | --- |
| X3 ≤ 3.5 m(벽 옆) 개체 수: 평균 / 최소 | 2.74 / **0** | 2.71 / **2** |
| X3 ≤ 3.5 m 개체가 하나도 없을 확률 | **7.4%** | 0% |
| R ≥ 2.4 m 개체 수: 평균 / 최소 | 9.5 / 1 | 9.5 / 9 |
| X1, X2, X3 모두 ≤ 3.5 m(다섯 기 모두 벽 옆) 개체가 있을 확률 | 0.35% | 0.05% |

- 변수 하나의 끝 영역은 LHS가 항상 덮는다. 난수는 열 번에 한 번꼴로 그 영역을 통째로 놓친다.
- 그러나 **"다섯 기 모두 벽 옆"인 구석은 두 방법 모두 거의 뽑지 못한다.**
  - LHS는 변수 하나하나를 고르게 할 뿐, 여러 변수의 조합까지 고르게 하지는 않는다.
  - 이 구석의 부피는 (0.5/22)³ ≈ 0.001%다.
  - 따라서 칠발도·영일만항에서 놓친 영역을 LHS만으로 직접 덮을 수는 없다.

**벤치마크 함수 (DE, 개체 100, 7차원, WEC 격자, 시드 30, 평가 30,000회)**
- 세 가지 조건에서 비교했다(실행 시간 각 12~14분, 20 프로세스).
  - 기본.
  - `--bounded`: 최소점을 범위 밖에 두어 최적점이 경계에 있게 한다. WEC 문제와 같은 상황이다.
  - `--bounded --rotate`: 위 조건에 변수끼리 얽힌 형태를 더한다.

| 조건 | 6개 함수의 최종값 (Mann-Whitney, DE+LHS 대 DE) |
| --- | --- |
| 기본 | 모두 p ≥ 0.12, 중앙값 같거나 거의 같음 |
| 경계 최적 | 모두 p ≥ 0.23, 두 방법 모두 대부분 최적점 도달 |
| 경계 최적 + 회전 | 모두 p ≥ 0.16 |

- 초반 진행도 비교했다. 평가 300, 1200, 3000, 9000회에서 중앙값의 비(LHS/난수)는 0.63~1.34로 양쪽에 흩어졌다. 한쪽이 꾸준히 앞서지 않았다.
- 결론: 이 크기(개체 100, 7차원, 평가 30,000회)에서 LHS는 DE의 결과를 바꾸지 않는다.
  - 문헌에서 초기화의 효과는 개체 수가 적거나 차원이 높거나 예산이 작을 때 커진다고 하는데, 이번 조건은 그 반대다.
  - 개체 100개를 무작위로 뽑아도 각 변수는 이미 꽤 고르게 덮인다.

## 5. 남은 이슈 / 후속 작업

- **실제 WEC 문제에서 확인하기**: 칠발도·영일만항을 `InitPop` 0과 1로 시드 몇 개씩 돌려 비교한다.
  - 계산용 PC에서 `Workers` 4, `DEUpdate` 2로 돌리면 한 번에 약 16 h다.
  - 벤치마크 결과로 보면 큰 차이는 기대하기 어렵다.
- **골짜기 선택 문제는 초기화보다 탐색 과정에 있을 가능성이 크다.**
  - DE/rand/1/bin은 CR 0.9에서 대부분의 변수를 변이 벡터에서 가져온다. 그래서 "X1이 작은 개체"와 "X3가 작은 개체"의 좋은 점을 합치기 어렵다.
  - 시드 비교로 결과의 편차를 먼저 확인한 뒤, 변이 전략(예: current-to-best)이나 CR을 검토할지 정한다.
