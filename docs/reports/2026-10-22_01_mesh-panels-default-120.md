# 업데이트 보고서: MeshPanels 기본값 120으로 상향과 5기 수렴 결과 정정

- 날짜: 2026-10-22
- 범위: `src/physics/mesh_axisymmetric_shape.py`, `config.cfg`, `tests/test_mesh.py`, `README.md`, `docs/algorithms_and_problems.md`, `CHANGELOG.md`, 보고서 `2026-10-21_09`, `2026-10-21_10`

## 1. 개요

개선 메쉬(보고서 09)를 도입할 때 5기 수렴을 R=2.5, D=5.0과 배치 한 가지에서 총 파워만 보고 "약 1% 이내, 단조 수렴"이라고 결론 내려 기본값을 80패널로 정했습니다. 설계와 배치를 넓히고 개별 WEC 파워까지 비교한 수렴 테스트 결과 80패널은 일부 설계에서 많이 틀려서, 기본값을 120패널로 올리고 이전 서술을 정정했습니다.

## 2. 변경 내용

- `DEFAULT_QUARTER_PANELS` 80 → 120 (`MeshPanels` 기본값). 5기 평가 시간은 약 6초에서 약 12초가 됩니다.
- `config.cfg`의 `MeshPanels` 안내를 수렴 테스트 결과(어느 형상에서 얼마나 틀리는지, 권장 패널 수, 메모리 한계)로 바꿨습니다.
- 보고서 09, 10, CHANGELOG, README, `docs/algorithms_and_problems.md`에서 80패널 관련 서술을 정정했습니다.
- `tests/test_mesh.py`에 기본값이 5기 메모리 경고 기준 안에 있고 모든 대표 형상에서 목표 근처로 맞는지 확인하는 테스트를 추가했습니다.

## 3. 호환성 영향

- 물리 해석 입력이 바뀝니다: 기본 설정에서 `wec.gdf` 패널 수가 늘어나(예: R=2.5, D=5.0에서 1/4 패널 81 → 약 120) 이전 기본값 결과와 파워를 직접 비교할 수 없습니다. 더 정확한 쪽으로 바뀌며, 값이 달라지는 정도는 아래 표와 같습니다.
- `wec.gdf.meta.json`의 `target_panels`가 달라지므로 기존 `workspace/`의 GDF는 다음 실행에서 자동으로 다시 만들어집니다.
- `MeshPanels`를 `config.cfg`에서 직접 지정한 경우에는 영향이 없습니다. 이전처럼 빠르게 돌리려면 `MeshPanels`를 80으로 지정하세요(정확도가 떨어집니다).

## 4. 검증

5기, 수직벽 켬, 영일만항(수심 13 m), `Solver=0`, `NCPU=8`. 기준(참값 대용)은 각 경우에서 가장 촘촘하게 돌린 메쉬(1/4 패널 160~205개)입니다. 괄호는 개별 WEC 중 최대 오차이고, 시간은 평가 1회입니다. 배치 A는 최소 간격 8.5 m, 배치 B는 6.0 m입니다. 열의 패널 수는 근사값이고(33~165패널 범위에서 설계마다 조금씩 다름) 마지막 열이 기준인 경우는 그렇게 표시했습니다.

- 평가 시간은 약 40패널 1~2초, 약 80패널 5~6초, 약 120패널 11~13초, 약 160패널 19~24초입니다.
- 80패널은 가늘고 긴 형상(R 작고 D 큼), 넓고 얕은 형상, 촘촘한 배치에서 총 파워 최대 11%, 개별 WEC 최대 18% 틀렸습니다. 개별 WEC 오차가 총합 오차보다 큽니다.
- 120패널은 대부분 총 파워 0.5% 이내, 개별 WEC 1.2% 이내이지만 가늘고 긴 형상(R=0.5, D=2.0)은 개별 WEC가 5%대로 남습니다. 이 형상은 160패널에서야 수렴했습니다.
- 수렴이 항상 단조로운 것은 아닙니다(R=2.5, D=5.0, 배치 B: 40패널 +3.6% → 80패널 +2.7% → 120패널 +0.2% → 160패널 +0.3%).
- 기준값은 완전 수렴한 참값이 아니라 가장 촘촘한 메쉬이므로 위 오차는 그에 대한 상대값입니다.
- R=2.5, D=0.5는 1/4 패널 224개(전체 1,120)에서 메모리 오류가 났습니다. 반복 솔버는 이 형상의 ω=3 rad/s에서 `MAXITT`에 도달했다는 경고도 냈습니다.
- py311에서 `ruff check .`, `ruff format --check .`, 단위 테스트 98건(skip 3) 통과. `config.cfg` 기본값으로 5기(R=2.5, D=5.0, 배치 A)를 실제 WAMIT에서 돌려 1/4 패널 120개(전체 600개), 10.6초, 17,970 W를 확인했습니다.

## 5. 남은 이슈 / 후속 작업

- 형상·배치마다 필요한 패널 수가 다릅니다. 하나의 기본값(120)으로는 가늘고 긴 형상이 부족하고 넓고 얕은 형상은 메모리 한계에 가깝습니다. 설정 범위의 최악 형상에서 수렴 패널 수와 메모리 한계를 함께 측정해 `MeshPanels`를 정하는 사전 점검 스크립트가 필요합니다.
- 평가 시간이 약 2배가 되었으므로 허용 평가 시간 기준을 정해야 합니다.
- 균일 0.05 간격 주파수 격자가 좁은 공진을 under-resolve하는 문제(보고서 10)는 그대로입니다.
