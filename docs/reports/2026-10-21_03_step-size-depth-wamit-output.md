# 업데이트 보고서: 변수별 격자 간격, 영일만항 수심 수정, WAMIT 출력 정리

- 날짜: 2026-10-21
- 범위: `data/env_data.csv`, `config.cfg`, `src/algorithms/common.py`, `src/utils/validation.py`, `src/problems/*`, `src/physics/wamit_handler.py`, `tests/test_step_size.py`(신규), 문서

## 1. 개요

1. 영일만항(Yeongilmanhang) 수심을 33 m에서 **13 m**로 바로잡았습니다.
2. 설계 변수마다 격자 간격(StepSize)을 `config.cfg`에서 따로 지정할 수 있게 했습니다.
3. 작업 중에 격자 상한이 부동소수점 오차로 누락되는 버그를 발견해 함께 고쳤습니다.
4. WAMIT이 사용하지 않는 출력(`.3`)을 껐습니다.

## 2. 변경 내용

### 2.1 영일만항 수심 (`data/env_data.csv`)
- `3,Yeongilmanhang,0.92,6.66,1.4,33`을 `...,13`으로 고쳤습니다. WAMIT `.pot`의 HBOT에 그대로 들어갑니다.

### 2.2 변수별 격자 간격
- `config.cfg`의 `[Constraints]`에서 `{변수}Step` 키로 지정합니다. 지정하지 않은 변수는 공통 `StepSize`를 씁니다.
  - 사용 가능 키: `RadiusStep`, `DraftStep`, `WEC1_XStep`, `WEC2_XStep`, `WEC2_YStep`, `WEC3_XStep`, `WEC3_YStep`
  - config에는 주석 처리된 예시 줄을 넣어 두었습니다. `#`을 지우면 적용됩니다.
- 검증(`resolve_step_sizes`, `src/utils/validation.py`):
  - 간격은 0보다 커야 합니다.
  - 간격은 (Max − Min) 이하여야 합니다.
  - 숫자가 아니면 `ConfigValidationError`가 납니다.
  - (Max − Min)이 간격으로 나누어떨어지지 않으면, 실제로 도달 가능한 상한을 담은 경고를 출력합니다. 예: `Radius 0.5~2.5`, 간격 0.3이면 실제 상한은 2.3입니다.
- 내부 구현:
  - `config["step_size"]`가 변수 순서대로의 리스트가 됐습니다. Joint 모드는 `[형상 간격들] + [배치 간격들]` 순서입니다.
  - 격자 스냅, 초기 개체 생성, 캐시 키, PSO 속도 상한, GA 변이 폭, CMA-ES σ 하한은 모두 원래 배열 연산이라 변수별 간격에 그대로 동작합니다.

### 2.3 격자 상한 누락 버그 수정 (`src/algorithms/common.py`)
- 기존 코드는 `floor((Max − Min) / step)`으로 최대 격자 인덱스를 구했습니다.
  - `(30 − 0.1) / 0.1 = 298.99999…` → 298이 되어 **상한 30.0이 탐색에서 빠졌습니다**(실제 최대 29.9).
  - 지난 업데이트에서 Y 하한을 0.1로 바꾼 뒤부터 실제로 발생하던 문제입니다.
- 상대 허용오차(1e-9)를 둔 `grid_max_indices()`로 통일했습니다. `quantize_vector`와 `random_grid_population`이 이 함수를 씁니다. 초기 개체도 10자리로 반올림합니다.

### 2.4 WAMIT 출력 정리 (`src/physics/wamit_handler.py`)
- `.frc`의 출력 옵션을 `1 1 1 0 0 0 0 0 0`에서 `1 1 0 0 0 0 0 0 0`으로 바꿨습니다.
  - `.1`(부가질량·감쇠)과 `.2`(Haskind 가진력)만 출력합니다.
  - `.3`(diffraction 가진력)은 `rao_calc`가 읽지 않으므로 계산과 파일 쓰기를 생략합니다.
- **WAMIT 입력 파일 변경**: 수정 전후 입력 파일을 비교했고(OptMode 1/2/3), 차이는 `wec.frc` 두 번째 줄의 이 옵션뿐입니다. 해석 결과(.1, .2)에는 영향이 없습니다.

## 3. 호환성 영향

- **영일만항 결과**: 수심 33 m로 계산한 기존 영일만항 결과가 있다면 무효이므로 다시 계산해야 합니다. 현재 프로젝트 `logs/`에는 영일만항 실행 기록이 없습니다.
- **수심 13 m의 물리적 의미**:
  - 영일만항 피크 주기 6.66 s의 심해 파장은 약 69 m이고, h/L₀ ≈ 0.19로 중간 수심 영역입니다.
  - WAMIT은 유한 수심(HBOT)을 반영합니다. 다만 파 스펙트럼은 심해형 JONSWAP 그대로입니다. 천해 보정(예: TMA 스펙트럼) 필요 여부는 검토 과제입니다.
  - 최대 총 흘수는 D + R = 7.5 m이고, 이때 바닥까지 여유는 5.5 m입니다.
- **config**: 기존 config는 그대로 동작합니다. `*Step` 키는 모두 선택 사항입니다.
- **문제 설정 dict**: `config["step_size"]`가 스칼라에서 리스트로 바뀌었습니다. 내부 함수는 스칼라도 계속 받습니다.
- **Y 하한 0.1과 간격의 조합**: Y 하한이 0.1이므로, Y 간격을 0.5처럼 키우면 상한이 29.6이 된다는 경고가 나옵니다. 상한 30을 그대로 쓰려면 `WEC2_YMin`/`WEC3_YMin`을 간격의 배수(예: 0.5)로 맞추세요.
- 이전 실행의 `wec.3` 파일은 더 이상 생성되지 않습니다.

## 4. 검증

- 단위 테스트는 38개에서 50개로 늘었고 모두 통과합니다. 추가된 `tests/test_step_size.py`:
  - 상한 도달성 (0.1~30 / 0.1, 0~0.3 / 0.1 등 부동소수점 경계 사례, 프로젝트 config의 Y 상한 30.0)
  - 기본 간격 적용, 변수별 지정 시 벡터 순서대로 적용되는지(Joint 5기)
  - 변수별 간격의 격자 스냅과 캐시 키, 초기 개체군이 각 변수 격자 위에 있는지
  - 잘못된 간격(0, 음수, 문자, 범위 초과, 미지정) 에러와 나누어떨어지지 않을 때 경고(실제 상한 2.3 표시)
  - 네 알고리즘의 모든 평가 벡터가 변수별 격자 위에 있는지
  - `.frc` 출력 옵션 확인, 영일만항 수심 13 m 확인
- `ruff check .`, `ruff format --check .` 모두 통과했습니다.
- WAMIT 입력 파일 비교: `.frc` 출력 옵션 한 줄 외에는 동일합니다.

## 5. 남은 이슈 / 후속 작업

- **IDIFF 설정**: `.3`을 끈 뒤에도 `IDIFF=0`이라 diffraction 문제 자체는 계속 풉니다. Haskind 가진력은 radiation 해만으로 계산되므로, `IDIFF=-1`로 diffraction 풀이를 생략할 수 있는지 WAMIT v7 매뉴얼과 실제 실행으로 확인한 뒤 적용할 예정입니다.
- **주파수 범위·분해능**: 해역별로 정해야 하므로 보류합니다. 아래 사전 점검 설계와 함께 진행합니다.
- **메시 밀도와 32-bit WAMIT 메모리 한계**: 사전 점검(preflight) 방식을 설계 중입니다(대화 기록 참고). 확정되면 별도 보고서로 남기겠습니다.
- **탐색 효율 개선**: 초기 개체군을 실현 가능한 해로 생성, 수리 연산자, 실제 WAMIT 실행 수 기준 예산, 정체 시 재시작, 마무리 국소 탐색 순으로 검토합니다.
- 이전 보고서의 남은 이슈(벽 조건 의도, 벽 이격 제약, 경계 해)는 그대로입니다.
