# 업데이트 보고서: 적응형 주파수 격자 옵션 `FreqGrid` (기본 끔)

- 날짜: 2026-10-23
- 범위: `src/physics/wamit_handler.py`, `src/problems/*.py`, `main.py`, `config.cfg`, `src/utils/run_summary.py`, 테스트, 문서

## 1. 개요

4차 시험(`2026-10-23_03` 보고서)에서 적응형 0.85~1.1 + 미세 0.00625 격자가 형상 4개 모두에서 총합 ≤0.13%, 최악 WEC ≤0.55%(0.003125 확인 격자 대비 ≤0.26%)로 균일 0.05보다 훨씬 정확하고 균일 0.0125보다 빠른 것이 확인되어, 이를 `FreqGrid=1`로 구현했다. 2단계 격자는 구현하지 않았다.

## 2. 변경 내용

- `config.cfg`: `FreqGrid`(0 균일, 1 적응형; 기본 0). `main.py`가 읽어 검증하고 `wamit_data`와 각 문제 설정(`freq_grid`)으로 전달한다.
- `wamit_handler.adaptive_omegas(radius, draft, omega_max)`: 시험 도구의 `adaptive_grid(0.85, 1.1, fine_step=0.00625, tail_ratio=1.5)`와 동일한 격자(테스트로 6개 형상 × 상한 2개에서 일치 확인). `w0 = sqrt(g/(D+2R/3))`, 경계는 0.0125 격자에 맞추고 구간 안은 0.00625 간격, 1.5·w0 위는 0.1 간격, 나머지는 0.05. 공진 구간이 `OmegaMax` 밖이면 구간이 없어 균일 격자(위쪽 꼬리 제외 없음)가 된다.
- `write_pot_file(..., omegas)`: `omegas`가 있으면 `NPER`를 양수로 하고 주파수(rad/s) 목록을 직접 쓴다(`IPERIN=2`, 시험 도구와 같은 형식). 없으면 기존 `-NPER`/시작·간격 형식 그대로.
- `run_summary`: `freq_grid` 열 추가.
- 테스트 `tests/test_freq_grid_option.py` 14건: 시험 도구 후보와의 일치, 정렬·범위, 창 안 간격, 폴백, 입력 검증, 기본/끔에서 기존 `.pot`와 동일, 켠 경우 명시 목록, 다른 입력 파일 불변, 비균일 목록 읽기.

## 3. 호환성 영향

- 기본값 0에서는 WAMIT 입력이 이전과 동일하다(`.pot` 텍스트 테스트). `config.cfg`에 `FreqGrid` 줄이 없어도 0으로 동작한다.
- `summary.csv`에 `freq_grid` 열이 추가된다(기존 결과 행은 빈 칸).
- `FreqGrid=1`이면 평가마다 주파수 수가 형상에 따라 다르다(시험에서 약 70~196점). 전력 적분은 `simpson(x=omegas)`라 비균일 격자를 그대로 쓴다. `B_pto`는 여전히 비제어 RAO 피크 노드의 `B_kk`이므로 격자와 함께 정확해진다.
- 켜면 평가 시간이 균일 0.05의 1.5~2.5배(시험: 1.5, 1.9, 2.5, 2.2배)가 된다.

## 4. 검증

- `ruff check .`, `ruff format --check .`, 단위 테스트 166건(skip 3) 통과(이전 152건).
- WAMIT 실행은 하지 않았다(구현 격자는 시험 도구의 검증된 후보와 같음을 테스트로 확인). 실제 최적화에서 켜서 확인하는 것은 계산용 PC에서 한다.

## 5. 남은 이슈 / 후속 작업

- 아주 좁은 공진(R≤0.5, D≥2.0)은 0.00625 간격이 경계에 가깝다(확인 격자 대비 최악 0.264%). 더 가는 형상이 탐색 범위에 있으면 2단계 격자 검토.
- `ω0 > OmegaMax`인 작은 WEC은 공진이 격자 밖이라 이 옵션이 균일 격자와 같아진다(`OmegaMax` 자동 확장은 미구현).
- `FreqAlign`(NCPU 정렬), 전체 `grids` 시험, 실제 최적화 시간 비교는 후속.
- 커밋/푸시 안 함.
