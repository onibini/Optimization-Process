# 업데이트 보고서: CMA-ES 보폭(sigma) 상한과 넘침 방지

- 날짜: 2026-10-23
- 범위: `src/algorithms/cma_es.py`, `tests/test_cma_es_sigma.py`(신규)

## 1. 개요

알고리즘 벤치마크(`2026-10-23_11` 보고서)에서 CMA-ES 실행 하나가 보폭 갱신 `sigma *= exp((cs/damps)(|ps|/E|N| - 1))`에서 `overflow`(무한대) 경고를 냈다. 보폭에는 격자 한 칸의 하한만 있고 상한이 없었다. 보폭이 하한에 묶이면 평균 이동량을 보폭으로 나눈 진화 경로 `ps`가 커지고, 다음 갱신의 지수가 매우 커질 수 있다. 보폭이 무한대가 되면 샘플이 범위 끝으로 몰리거나 NaN이 되어 탐색이 망가진다.

## 2. 변경 내용

- `update_sigma(sigma, ps_norm, cs, damps, echi, min_sigma, max_sigma=MAX_SIGMA)`를 분리했다.
  - 한 세대의 로그 변화량을 `MAX_LOG_SIGMA_CHANGE = 1.0` 이하로 제한한다. 즉 한 세대에 최대 e배(≈2.7배)까지만 커진다. pycma와 같은 방식이다.
  - 결과를 `[min_sigma, MAX_SIGMA]`로 제한한다. `MAX_SIGMA = 1.0`은 정규화 공간에서 범위 전체를 뜻한다. 샘플이 [0, 1]로 잘리므로 그보다 큰 보폭은 의미가 없다.
  - 보통의 갱신(지수가 1 이하)은 표준식과 같다.
- `SigmaInit`이 (0, 1] 밖이면 시작할 때 오류를 낸다. 기존 기본값 0.3은 그대로다.

## 3. 호환성 영향

- 보폭이 크게 커지는 드문 경우에만 결과가 달라진다. 보통의 실행은 같은 난수에서 같은 결과를 낸다(지수가 1을 넘지 않는 한 식이 같음).
- `SigmaInit`은 0보다 크고 1 이하여야 한다.
- 계산용 PC에서 돌고 있는 작업 `20261023_161543_cmaes_sites`는 **수정 전 코드**로 돌고 있다(작업 시작 때 코드를 복사함). 2026-10-23 확인 시점(부안 21세대)까지 로그에 overflow는 없었다.

## 4. 검증

- 테스트 5건: 진화 경로 크기 1e300에서도 넘침 경고 없이 유한값(변화량 상한 적용), 상한·하한, 보통의 갱신은 표준식과 같음, 잘못된 `SigmaInit`(0, 음수, 1.5) 거부, `SigmaInit=1.0`에서도 수렴.
- `ruff check .`, `ruff format --check .`, 전체 단위 테스트 통과.

## 5. 남은 이슈 / 후속 작업

- 돌고 있는 CMA-ES 작업을 수정된 코드로 다시 시작할지는 사용자 결정. 진행 속도로 보면 부안 한 곳에 약 35시간(세대당 약 7분, 고유 평가 약 53회)으로, 처음 예상(해역당 12~24시간)보다 길다. 같은 점 반복(캐시 적중)이 아직 0회이고, 샘플의 약 27%가 간격 제약 위반(패널티, WAMIT 없음)이다.
- 알고리즘 벤치마크의 CMA-ES 결과는 수정 전 코드다. 다시 돌리면 overflow가 났던 실행 하나만 바뀔 수 있다.
